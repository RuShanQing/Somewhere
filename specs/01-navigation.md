# NAV · 四大导航与全局交互

**优先级：P0** · 归属：Web 前端 / 共享 API 会话管理

> 实现状态（2026-10-28）：四导航、路由守卫、登录/注册页、设置页、空态、键盘与移动端基础已由 TASK-001/TASK-003 实现；邮局三栏、写信页与明信片详情已由 TASK-004 实现；发现、共途、纪念册的业务页仍未实现。

## NAV-01 目标

用户第一次进入 Somewhere，能够辨认邮局、发现、共途、纪念册的分工；任何业务入口都能回到相应主导航。桌面 Web 可采用适当的响应式导航样式，但产品语义仍是四个固定主入口。

## NAV-02 路由

| 模块 | 路由 | 默认子页面 | 登录要求 |
|---|---|---|---|
| 邮局 | `/post-office` | 新来信 / 在途 / 草稿概览 | 必须登录 |
| 发现 | `/discover` | 城市故事站 | 允许匿名查看审核公开故事；参与操作需登录 |
| 共途 | `/passages` | 我正在进行的共途 | 必须登录 |
| 纪念册 | `/memories` | 双城日记 / 个人记忆 | 必须登录 |
| 设置 | `/settings` | 昵称 / 城市 / 接信状态 | 必须登录 |
| 邮局写信 / 明信片详情 | `/post-office/compose/:id?`, `/postcards/:id` | 非主导航的邮局子页面 | 必须登录 |
| 登录 / 注册 | `/auth/login`, `/auth/register` | 账号入口 | 匿名可访问 |

路由不含 email、精确坐标或一次性会话信息。详情页通过 `/:id` 访问，但服务端仍进行权限检查。

## NAV-03 页面状态

每个页面必须完整处理 `loading / empty / error / ready` 四态：
- `empty` 不伪造故事、来信、共途，也不能把“API 错误”当成“空”。
- 无权限展示统一的温和提示及下一步操作，不泄露私有资源是否真实存在。
- 未实现的 P1 功能可标记“暂未开放”，不得做看似可点却无结果的假按钮。
- 主导航切换保留可理解的当前选中状态，刷新页面不重置到错误路由。

## NAV-04 可访问性与交互

- 表单有 label，必填与错误状态可供辅助技术读取；按钮必须有实际操作或明确禁用理由。
- 键盘能够导航主菜单，交互元素有清晰焦点。
- 在途倒计时仅作展示，不代表服务器事实源；不得通过客户端改时钟提前开启信件。
- 暂不展示“某人在线”“某人已读”“连续回信天数”。

## NAV-05 数据/API 边界

导航自身不应保存所有业务列表；登录会话通过 `GET /api/v1/auth/me` 获取，页面数据按各自的领域 API 获取。私有页面受前端路由守卫和后端鉴权双层保护。

## NAV-06 验收（当前任务可执行）

- 有效会话用户可访问四主页面；无数据时展示真实空态。
- 未登录访问邮局、共途、纪念册时进入登录流程，且不闪烁私人内容。
- 直接刷新任一已实现路由，页面不出现 404 或无限重定向。
- 主要入口可以键盘操作，浏览器返回行为符合路由历史。
- 所有公开故事入口都只来自已批准的内容 API。

**不在本规范中决定最终视觉风格、动效或地图的渲染技术。**
