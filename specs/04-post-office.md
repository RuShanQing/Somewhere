# POSTOFFICE · 邮局首页与三类信件

**优先级：P0** · 主导航：邮局 · 归属：PostcardModule / PostOffice Web

> 实现状态（2026-10-28，TASK-004）：已实现 `/post-office` 三栏摘要、`/post-office/compose` 写信页、`/postcards/:id` 详情页，以及加载/空/错误/重试、390px 与键盘基础。摘要不返回正文；收件人在途详情返回 404。**尚未实现**：回信、通知、举报/封锁/审核隔离；这些能力不得在 UI 中以可用按钮伪装。

## POSTOFFICE-01 目标

用一个安静、可信的信箱呈现「新来信、正在路上的信、继续写信」。不做实时聊天收件箱、不催促回信、不制造已读压力。

## POSTOFFICE-02 页面构成

| 区域 | 内容 | 点击行为 |
|---|---|---|
| 新来信 | 当前用户有权阅读、已到达的明信片，按实际送达时间倒序 | 开启详情 / 自愿回信 |
| 正在路上的信 | 本人已寄出但尚未投递、已知 `deliverAt` 的明信片 | 查看邮路状态、本人寄出的内容 |
| 继续写信 | 本人未发送的草稿，按 `updatedAt` 倒序 | 返回编辑器 |
| 空态 | 未有来信/在途/草稿时显示友好但真实的说明 | 引导写明信片或发现故事 |

只有寄件人能在途查看自己的正文；收件人送达前不能从任何预览或通知获取正文。默认不显示“收件人已读”。

## POSTOFFICE-03 业务规则

- 已寄出与草稿是不同实体；点击“继续写信”不会产生真实投递。
- 到期展示以服务端 `status / deliverAt` 为准，前端倒计时可作为提示但不改变送达结果。
- 一张信只进入自己适当的列表，不因列表切换改变状态。
- 收件人若选择不回信，来信不会产生待办任务、亏欠标记或连续天数压力。
- 历史来信长期访问权由 [11-memories.md](11-memories.md) 的可见性与删除政策决定，邮局不自行扩大权限。

## POSTOFFICE-04 API

`GET /api/v1/post-office/summary`：
```json
{
  "incoming": [{"id":"pc_1","senderNickname":"远方来信","deliveredAt":"2026-10-27T08:00:00Z"}],
  "inTransit": [{"id":"pc_2","deliverAt":"2026-10-30T08:00:00Z","stage":"TRAVELING"}],
  "drafts": [{"id":"draft_3","updatedAt":"2026-10-26T07:00:00Z"}]
}
```
这只是响应**结构示例**，不是服务器真实数据。列表支持分页；敏感正文不进入 summary。`stage` 是象征性的视觉阶段，不能据此推断真实物流位置。

TASK-004 实际补充的登录接口：`GET /postcards/recipients`（演示白名单）、草稿 CRUD、`POST /postcards/drafts/:id/send`、`GET /postcards/transit`、`GET /postcards/inbox`、`GET /postcards/:id`。所有路径都带 `/api/v1` 前缀。

## POSTOFFICE-05 异常与权限

- 未登录 → 401；收件人试图提前读信 → 404 / 403（按统一防枚举规则）。
- 数据加载失败 → 错误态 + 重试，不能误报“没有信”。
- 被安全处理撤回/拦截的内容 → 显示不含正文与举报细节的统一受限态。
- 页面上所有数字和状态都来自当前用户授权范围内的 API。

## POSTOFFICE-06 验收

- 新用户看到三个合法空态，不出现伪造信件。
- 草稿保存后仅出现在“继续写信”；成功发送后从草稿消失并进入“正在路上”。
- 在途收件人无法通过 URL、接口或通知预览正文；寄件人可以查看自己的已寄出内容。
- 送达后自动进入收件人“新来信”；刷新页面状态不回退。
- UI 中没有在线状态、强制已读、催回信或连续聊天分数。
